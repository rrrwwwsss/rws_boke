## 张量

```python
x = torch.randn(2, 128, 4096)
```

它的三个数字可以这样理解：

- `2`：一次处理两句话，也就是 batch size 为 2。
- `128`：每句话有 128 个 Token。
- `4096`：每个 Token 用 4096 个数字表示。

这里的“维度”通常指最后一个数字 `4096`。如果执行：

```python
up = nn.Linear(4096, 16384)
y = up(x)
```

输出形状会变成：

```text
(2, 128, 4096) → (2, 128, 16384)
```

句子数量没变，Token 数量也没变，只是每个 Token 的表示从 4096 维变成了 16384 维。

## FFN 先升维后降维

**升维**：可以把一个 Token 的 4096 维表示想象成一张写得很挤的草稿纸。语法、语义、实体、语气等信息都叠在一起，不方便继续加工。

升到 16384 维，相当于换成一张更大的桌子，把原来挤在一起的信息摊开。模型因此有更多“位置”去组合特征：哪些信息应该放大，哪些应该抑制，哪些特征只有同时出现才有意义。

所以，升维并不是凭空增加知识，也不是增加 Token，而是给每个 Token 提供更大的中间处理空间。

**降维**：而高维空间适合加工，却不适合一直保留。每一层都维持 16384 维，会显著增加参数量、显存占用和计算量。

因此，FFN 完成特征组合后，再把结果压回 4096 维。

这像是在大桌面上整理资料，最后把有用结论浓缩回一页摘要。输出恢复成 4096 维后，才能和残差分支相加，也方便把许多 Transformer 层按相同接口堆叠起来。

## 典型 FFN 升维降维可以简化成：

```python
ffn = nn.Sequential(
    nn.Linear(4096, 16384),
    nn.GELU(),
    nn.Linear(16384, 4096),
)
```

中间的 `GELU`、`SiLU` 等非线性激活很重要。如果只把两个线性层首尾相连，中间没有非线性变化，那么数学上它们仍然可以合并成一个线性变换，升维的意义会大打折扣。

现在许多大模型使用 SwiGLU。它通常包含 `gate_proj`、`up_proj` 和 `down_proj`：前两个投影到更大的中间空间，经过门控后，再由 `down_proj` 压回隐藏维度。具体中间维度不一定恰好是隐藏维度的 4 倍，要以模型配置为准。


## LoRA 的“降维”

LoRA 也有先降维、再升维的过程，但它解决的问题和 FFN 不一样。

假设原线性层为：

```python
linear = nn.Linear(4096, 4096)
```

完整微调需要更新一个约有 1678 万个参数的权重矩阵。LoRA 冻结原权重，只为它增加一条较小的旁路：

```text
4096 → r → 4096
```

如果 `r = 8`，这条旁路可以直观地写成：

```python
lora_A = nn.Linear(4096, 8, bias=False)   # 降到低秩空间
lora_B = nn.Linear(8, 4096, bias=False)   # 再映射回原空间

output = original_linear(x) + lora_B(lora_A(x)) * scale
```

LoRA 新训练的参数量只有：

```text
4096 × 8 + 8 × 4096 = 65,536
```

它远小于完整矩阵的：

```text
4096 × 4096 = 16,777,216
```

## LoRA 为什么可以压到很低的 Rank

LoRA 的核心假设是：一个大模型适应某项新任务时，真正需要学习的权重变化，往往不需要动用原矩阵的全部自由度。

用白话说，大模型本来已经会说话、会理解文字。微调“公路违法识别”时，不需要把它从头教一遍，只需要调整少量方向，让它更熟悉新的术语、格式和判断习惯。

LoRA 先把输入投影到很小的 `r` 维空间，在这里学习最重要的变化方向，再映射回原来的维度，并加到原线性层结果上。这里的低维空间更像一张“修改清单”，而不是模型完整的知识空间。

## FFN 和 LoRA 不要混在一起

| 对比项 | FFN 升维再降维 | LoRA 先降维再升维 |
|---|---|---|
| 主要目的 | 给每个 Token 更大的特征加工空间 | 用更少参数表示权重更新 |
| 是否属于模型主干 | 是 | 不是，是附加旁路 |
| 中间维度 | 通常比隐藏维度大 | Rank 通常远小于隐藏维度 |
| 输出维度 | 回到隐藏维度，方便残差连接 | 回到原层输出维度，与原结果相加 |
| 主要收益 | 提高非线性表达能力 | 降低可训练参数、梯度和优化器显存 |

一句话概括：**FFN 是先把问题摊开再浓缩，LoRA 是先提炼少数修改方向，再把修改还原到原空间。**

## 常见误区

### 升维不是增加 Token

`(2, 128, 4096) → (2, 128, 16384)` 中，Token 仍然是 128 个，只是每个 Token 携带的中间特征更多。

### 降维不等于量化

降维改变矩阵或向量的形状；量化则是用更少的 bit 保存数字，例如把 FP16 权重改成 4 bit。两者不是一回事。

### LoRA 没有把模型输出永久压成 r 维

低秩空间只存在于 LoRA 旁路内部。旁路最后仍会映射回原维度，因此不会破坏主干网络的输入输出接口。

### LoRA 不是分解原始权重

原始权重仍然保留并冻结。LoRA 用两个小矩阵近似的是微调产生的权重增量 `ΔW`，不是拿两个小矩阵替换原始权重 `W`。
