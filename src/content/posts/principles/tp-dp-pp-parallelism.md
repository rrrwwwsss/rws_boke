## 三种并行分别切什么

多卡并行并不是一个开关，而是三种不同的切分维度：

| 策略 | 切分对象 | 每张卡是否有完整模型 | 主要目标 |
|---|---|---|---|
| TP 张量并行 | 一层内部的权重和计算 | 否 | 让单个模型跨多卡运行 |
| DP 数据并行 | 请求或训练样本 | 是 | 提高整体吞吐 |
| PP 流水线并行 | 不同网络层 | 否 | 容纳更深、更大的模型 |

实际系统可以组合它们。例如 16 张卡可以组成 2 路 PP、4 路 TP，再复制成 2 个 DP 副本。

## TP：拆分一层中的矩阵计算

Tensor Parallelism 将同一层的大矩阵沿行或列切到多张 GPU。每张卡完成部分矩阵乘法，再通过 All-Reduce、All-Gather 等集合通信组合结果。

优点是每张卡只保存部分权重，适合模型无法装入单卡的情况；缺点是几乎每层都会通信，对 GPU 间带宽和延迟非常敏感。因此，TP 通常优先放在 NVLink 或 NVSwitch 连接的单机内部。

TP 的数量也不应盲目增加。模型本来能放入单卡时，过度切分可能让通信成本超过并行收益。

## DP：复制模型并切分请求

Data Parallelism 在每个副本中保存完整模型，再把不同样本或请求交给不同副本。

训练时，各副本独立完成前向与反向传播，然后同步梯度；推理时，各副本可以处理不同请求，通常更接近“多实例 + 路由”，但成熟框架还需要处理批处理、负载均衡、状态和缓存亲和性。

DP 一般不能让单个请求更快，也不能让超出单卡显存的模型突然装入单卡。它擅长的是横向扩大总吞吐和服务容量。

## PP：按网络层切成多个阶段

Pipeline Parallelism 把连续层分配给不同 GPU。例如前 20 层位于 GPU 0，后 20 层位于 GPU 1。激活值沿阶段依次传递。

如果一次只处理一个 micro-batch，前一阶段算完后可能空闲，形成 pipeline bubble。训练通常用多个 micro-batch 交错填充流水线；在推理场景中，PP 的延迟和调度也需要谨慎评估。

PP 的优势是相邻阶段只需传递激活值，不像 TP 那样每层进行高频集合通信，因此在没有高速卡间互联、模型层结构又适合均匀划分时可能更实用。

## 该怎么选择

### 模型单卡能装下

优先用单卡副本，通过 DP 或多个服务实例扩大吞吐。这样通信最少，故障隔离也更简单。

### 模型单卡装不下，但单机多卡能装下

优先评估 TP。高速互联通常能让层内通信成本保持在可接受范围。

### 模型跨节点或层数适合分段

考虑 PP，或者将 PP 与节点内 TP 组合。需要检查阶段间负载是否均衡，避免某一阶段成为瓶颈。

### 既要容纳大模型又要高吞吐

先用 TP/PP 形成一个可运行的模型副本，再用 DP 复制多个副本。

## 一个简单的规模关系

如果总 GPU 数为 `world_size`，采用 TP、PP、DP 混合并行，通常满足：

```text
world_size = TP × PP × DP
```

这只是设备数量关系，不代表三个维度能随意组合。模型结构、KV Cache、通信拓扑和框架实现都会限制可行配置。

## 验证时不要只看显存

至少同时记录：

- 单请求端到端延迟；
- 首 Token 和后续 Token 延迟；
- 每秒请求数与每秒 Token 数；
- GPU 利用率和通信占比；
- 不同序列长度下的结果；
- 跨节点网络带宽与尾延迟。
