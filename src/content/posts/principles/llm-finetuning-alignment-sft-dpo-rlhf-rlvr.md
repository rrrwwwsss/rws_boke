## 先看完整关系图

```text
后训练/对齐方法
│
├── 监督学习类
│   ├── SFT：学习“问题 → 标准答案”
│   └── 直接偏好优化 ────────────────────────────────────│
│       ├── DPO                                         │
│       ├── IPO                                         │
│       ├── KTO                                         │
│       └── ORPO                                        │   
│                                                       │──────模型对齐
└── 强化学习训练                                         │
    ├── RLHF：奖励来自人类反馈或人类偏好训练出的奖励模型────│
    │   ├── PPO                                         │
    │   └── GRPO                                        │
    │                                                   │ 
    └── RLVR：奖励来自可自动验证的规则────────────────────│ 
        ├── PPO
        └── GRPO

```

最容易混淆的地方是：这些名词不在同一个层级。

- **SFT** 监督学习，使用标准答案训练。
- **DPO** 监督式、离线偏好优化，使用 chosen/rejected 数据；不运行在线强化学习。
- **IPO、KTO、ORPO** 和 DPO 同级的直接偏好优化方法。
- **RLHF** 强化学习框架，强调奖励信号来自人类反馈。
- **RLVR** 强化学习框架，强调奖励来自答案校验器、单元测试或规则。
- **PPO、GRPO** 是负责更新模型参数的具体强化学习算法。


## 先分清微调、后训练和对齐

**预训练**模型学到的是海量文本中的统计规律，核心任务是预测下一个 Token。它可能拥有很多知识，却不一定会按人类希望的方式回答问题。

因此，模型完成预训练后，通常还要经过后训练：

“后训练”是一个大范围概念，SFT、DPO、RLHF 和 RLVR 都可以属于后训练。

模型对齐则更强调让模型行为符合人类偏好、安全规则或任务目标。


## SFT：先教模型什么是正确回答

SFT 的全称是 Supervised Fine-Tuning，也就是监督微调。

它使用的数据一般长这样：

```json
{
  "prompt": "法国的首都是哪里？",
  "answer": "法国的首都是巴黎。"
}
```

训练时，模型看到问题和标准答案，通过交叉熵损失学习提高标准答案中每个 Token 的概率。

用白话说，SFT 就像老师把参考答案直接交给学生，让学生照着正确示范练习。

### SFT 擅长什么

- 教会模型遵循指令格式。
- 让模型适应某个专业领域。
- 固定输出结构，例如 JSON、报告模板或工具调用格式。
- 教模型模仿高质量推理过程和回答风格。

### SFT 的局限

SFT 只能告诉模型“这个答案应该怎样写”，不擅长表达两个看起来都合理的答案中哪个更好。

如果强行用单一标准答案训练，模型可能只会模仿示范，无法充分理解简洁、礼貌、安全、真实等比较模糊的偏好。

因此，许多模型会先做 SFT，再进入偏好对齐或强化学习阶段。但这不是绝对规定：例如 DeepSeek-R1-Zero 展示过不经过前置 SFT、直接进行大规模强化学习的路线。

## 偏好数据和 SFT 数据有什么区别

偏好数据通常提供同一问题下的两个回答，并标明哪个更好：

```text
问题
├── chosen：人类更喜欢的回答
└── rejected：人类不喜欢的回答
```

例如：

```text
问题：如何安全地清理电脑磁盘？

chosen：先检查磁盘占用，确认目录，再删除明确无用的缓存。
rejected：直接执行 rm -rf 清理所有文件。
```

偏好对齐的目标不是简单复述 chosen，而是让模型在以后遇到类似问题时，更倾向于生成具有 chosen 特征的回答。

## DPO：直接学习“哪个回答更好”

DPO 的全称是 Direct Preference Optimization，即直接偏好优化。

它使用 `prompt + chosen + rejected` 数据，直接提高 chosen 相对 rejected 的概率，同时使用参考模型约束新模型不要偏离得太远。

```text
偏好数据
   ↓
DPO 损失
   ↓
直接更新策略模型
```

DPO 最重要的特点是：**不需要先训练一个独立奖励模型，也不需要在训练过程中不断生成新回答并执行在线强化学习。** 原始 DPO 论文把经典 RLHF 目标重新参数化，转化成一种较简单的分类式损失。

### DPO 的优势与局限

## 优势

- 训练流程比经典 RLHF 简单。
- 不需要同时维护策略模型、奖励模型和价值模型。
- 使用离线偏好数据即可训练。
- 训练通常比 PPO 式 RLHF 更稳定、更容易复现。

## 局限

- 效果高度依赖偏好数据的质量和覆盖范围。
- 普通离线 DPO 不会持续探索模型尚未生成过的新回答。
- 如果 chosen 和 rejected 差异太明显，模型学到的偏好信息可能有限。
- 参考模型、数据分布和超参数仍会影响最终效果。

DPO 不是强化学习算法。虽然它解决的是与 RLHF 相近的偏好优化目标，但训练形式更接近监督学习。

## RLHF：把人类偏好变成奖励

RLHF 的全称是 Reinforcement Learning from Human Feedback，即基于人类反馈的强化学习。

经典 InstructGPT 式流程通常包含三个阶段：

```text
第一步：SFT
人类示范 → 训练一个会基本遵循指令的模型

第二步：奖励模型 RM
人类对多个回答排序 → 奖励模型学习人类偏好

第三步：强化学习
策略模型生成回答 → RM 给分 → PPO 等算法更新策略模型
```

奖励模型的作用像一名自动阅卷员。人类不可能为模型训练过程中生成的每一条回答实时打分，所以先用有限的人类排序数据训练 RM，再让 RM 为大量新回答提供分数。

## PPO：经典 RLHF 常用的更新算法

PPO 的全称是 Proximal Policy Optimization，即近端策略优化。

它的核心思想是：模型应该朝高奖励方向更新，但每次不要走得太远。

```text
目标 = 奖励模型分数 - β × KL散度
```

**奖励分数作用**是鼓励模型生成高分回答
**β × KL散度**的作用是约束模型不能离原始语言模型太远。β是KL 惩罚系数；KL散度是参考模型离原始语言模型的偏离程度


## GRPO：用组内比较替代价值模型

GRPO 的全称是 Group Relative Policy Optimization，即组相对策略优化。DeepSeekMath 将它描述为 PPO 的一种变体，目标之一是降低 PPO 的训练资源消耗。

它针对同一个问题一次生成一组回答，然后比较这组回答的奖励。

```text
同一个问题
├── 回答 A：奖励 1
├── 回答 B：奖励 0
├── 回答 C：奖励 1
└── 回答 D：奖励 0.5
        ↓
计算组内相对优势
        ↓
提高高于组内基准的回答概率
降低低于组内基准的回答概率
```

## PPO和GRPO的区别

**PPO**基线是Critic 价值网络预测的“预期得分” 。Critic（评论家/价值网络） 是强化学习中的一个独立神经网络，它的唯一任务是：预测“当前状态大概能拿多少分”。

举例就是：
教练看你上场前说：“以你的水平，这场大概能拿 70 分。”

你实际拿了 85 分 → 超常发挥（优势 +15），鼓励

你实际拿了 50 分 → 发挥失常（优势 -20），批评

基线 = 教练的预期值（Critic 预测的）

**GRPO**使用同组回答的奖励统计量构造相对基线，因此可以省掉独立价值模型，降低显存和系统复杂度。

同一个问题你做了 8 遍，得分分别是：

text
[90, 60, 75, 80, 70, 85, 65, 75]
平均分 = 75
某次拿了 90 → 高于平均（优势为正），鼓励

某次拿了 60 → 低于平均（优势为负），抑制

基线 = 组内平均分

## RLVR：让可以自动验对错的任务提供奖励

RLVR 的全称是 Reinforcement Learning with Verifiable Rewards，即基于可验证奖励的强化学习。

它适合存在**明确自动校验规则**的任务：

- 数学题：最终答案是否正确。
- 编程题：代码是否通过单元测试。
- 逻辑题：结果是否满足约束。
- 结构化输出：格式和字段是否符合要求。
- 工具调用：参数与执行结果是否正确。

以数学题为例：

```text
模型生成解题过程和答案
          ↓
答案校验器检查最终答案
          ↓
正确：奖励 1；错误：奖励 0
          ↓
GRPO 或其他 RL 算法更新模型
```

RLVR 的优势是奖励便宜、客观、可扩展。系统不需要请人逐条评价，也不一定需要训练一个主观奖励模型。

### RLVR 和 RLHF 的区别

| 对比项 | RLHF | RLVR |
|---|---|---|
| 奖励来源 | 人类偏好或由其训练的 RM | 程序、规则、测试或答案校验器 |
| 擅长任务 | 有用性、风格、安全性等主观目标 | 数学、代码等可明确验证的任务 |
| 奖励成本 | 标注和奖励模型成本较高 | 自动验证后边际成本较低 |
| 主要风险 | 标注偏差、奖励模型漏洞 | 只优化最终答案、钻验证规则空子 |
| 可用算法 | PPO、GRPO 等 | GRPO、PPO 等 |

二者不是绝对互斥的。实际系统可以同时使用规则奖励、可验证奖励和模型奖励。例如推理模型可能用答案正确性奖励训练数学能力，同时用人类偏好或模型评价改善表达、安全性和可读性。

## 为什么 GRPO 常和 RLVR 一起出现

GRPO 和 RLVR 很搭配，主要有三个原因。

第一，可验证任务能为同一道题的多条回答快速打分，非常适合做组内比较。

第二，数学和代码任务的奖励通常比较稀疏。模型可能生成多条不同路径，组内相对奖励能指出哪些路径比同组平均水平更好。

第三，省去价值模型后，可以把更多显存留给策略模型、参考模型和多条采样结果。这对大模型推理训练非常重要。

但不能由此得出“RLVR 就等于 GRPO”。

```text
RLVR：奖励从哪里来
GRPO：拿到奖励后怎么更新
```

它们属于两个不同维度，只是经常组合使用。

## 一条常见的完整训练路线

一个实际模型可能依次经历：

```text
1. 预训练
   学语言、知识和基础能力

2. SFT
   学指令格式、领域任务和高质量示范

3. DPO 或 RLHF
   学人类偏好、回答风格和安全边界

4. RLVR + GRPO
   用数学答案、代码测试等强化可验证推理能力

5. 再次 SFT 或偏好对齐
   改善强化学习后可能出现的可读性和风格问题
```

这只是常见组合，不是固定流水线。团队会根据数据、任务和资源调整顺序，有些阶段也可能重复多轮。

例如：

- 普通领域问答模型可能只需要 SFT + DPO。
- 通用聊天模型可能使用 SFT + 奖励模型 + PPO。
- 数学推理模型可能使用 SFT + RLVR + GRPO。
- 探索型研究可能跳过前置 SFT，直接观察纯 RL 能否产生推理行为。

## 最容易出现的几个误区

### 误区一：DPO 是一种强化学习算法

不是。DPO 使用偏好数据解决与 RLHF 相近的目标，但通常采用离线的监督式损失训练，不需要在线 RL 循环。

### 误区二：RLHF 就是 PPO

不是。RLHF 是利用人类反馈构造奖励并优化模型的流程；PPO 是这个流程中可以选用的一种策略优化算法。

### 误区三：GRPO 只能用于 RLVR

不是。GRPO 不关心奖励来自人类奖励模型还是答案校验器。只是因为它适合组内采样和节省价值模型显存，所以在 RLVR 推理训练中很常见。

### 误区四：RLVR 属于偏好对齐

不一定。RLVR 主要优化可验证的任务目标，不需要人类比较两个回答哪个更好。它属于强化学习后训练，但奖励信号和经典偏好对齐不同。

### 误区五：SFT、DPO 和 RL 只能三选一

不是。它们经常前后组合。SFT 提供稳定起点，DPO 学习离线偏好，RL 通过在线采样继续探索，分别解决不同问题。

## 最后用一句话记住它们

- **SFT**：老师给标准答案，模型照着学。
- **DPO**：老师给两个答案，模型直接学习更喜欢哪一个。
- **RLHF**：先训练一名模仿人类偏好的评分老师，再让模型根据评分练习。
- **PPO**：每次朝高分方向走一点，但不要走太猛。
- **GRPO**：同一道题生成一组答案，比较谁高于组内平均水平。
- **RLVR**：不用人类主观打分，让答案校验器或测试程序直接判定结果。

真正的关系不是一条简单的升级路线，而是两条轴：

```text
奖励从哪里来：人类偏好 / 奖励模型 / 可验证规则
模型怎么更新：DPO / PPO / GRPO / 其他优化算法
```

先分清“奖励来源”和“优化算法”，SFT、DPO、RLHF、PPO、GRPO、RLVR 的关系就不会再混乱。
