## 先说结论

Transformer 强，不是因为它发明了某一个神奇公式，而是因为它把几件重要的事组合到了一起：

- 训练时可以同时处理所有 Token，更适合 GPU。
- 任意两个 Token 都能直接交换信息，更容易学习长距离关系。
- 注意力负责从上下文中选择信息，FFN 负责对每个 Token 继续加工。
- 缩放、残差连接和归一化让深层网络更容易稳定训练。
- 位置编码补上了词序信息。

RNN、CNN 不是完全做不到这些事，而是完成同样目标时，往往需要更长的信息传递路径，或者更难发挥现代 GPU 的并行算力。

## 1. 所有 Token 可以并行计算

假设输入是：

```text
猫 追 狗
```

RNN 的处理方式像接力赛：先处理“猫”，得到隐藏状态；再把隐藏状态交给“追”；最后才能处理“狗”。第 3 步依赖第 2 步，第 2 步又依赖第 1 步。

```text
猫 → 追 → 狗
```

这导致同一句话内部很难完全并行。即使 GPU 有大量计算核心，也必须等待前一步完成。

Transformer 在训练时可以把整句话的 Token 一起送入注意力层：

```text
猫 ┐
追 ├─→ 同时计算
狗 ┘
```

每个 Token 的 Query、Key、Value 可以通过大规模矩阵乘法同时算出。矩阵乘法正是 GPU 擅长的工作，因此 Transformer 很容易随着更多数据、更大模型和更多计算资源扩展。

这里要注意：**训练阶段可以并行处理输入 Token，不代表大模型生成回答时也能一次生成所有 Token。** 自回归生成仍然需要逐 Token Decode，因为下一个 Token 依赖前面已经生成的结果。

## 2. 任意两个 Token 可以直接建立关系

看下面这句话：

```text
小明把钥匙放在桌子上，离开房间之前，他又把它拿走了。
```

模型需要知道“它”指的是前面的“钥匙”。

在 RNN 中，前面的信息要沿着隐藏状态一步一步传到后面。距离越远，中间经过的步骤越多，信息越容易被覆盖或衰减。LSTM 和 GRU 使用门控机制缓解了这个问题，但信息仍然需要沿序列传递。

在一层自注意力中，“它”可以直接查看“钥匙”的表示。无论两个词相隔 2 个 Token，还是 200 个 Token，它们在注意力图中的连接路径都可以只有一步。

```text
钥匙 ─────────────→ 它
```

这不意味着 Transformer 永远不会忘记长文本。上下文窗口、注意力分散、位置表示和训练数据都会影响长文本能力。但从网络结构看，它为远距离 Token 提供了更直接的信息通道。

## 3. 为什么注意力分数要除以 `√d_k`

缩放点积注意力的核心公式是：

```text
Attention(Q, K, V) = softmax(QKᵀ / √d_k)V
```

`QKᵀ` 可以理解为 Token 之间的相关性打分，`d_k` 是 Query 和 Key 的维度。

当维度很大时，点积的数值也容易变大。例如得到下面一组分数：

```text
[2, 4, 20]
```

经过 Softmax 后，最大的那个值可能几乎独占全部权重。其他位置的概率接近 0，梯度也会变得很小，模型很难继续调整“应该关注谁”。

除以 `√d_k` 相当于给分数降温，把数值拉回比较稳定的范围：

```text
过大点积 → 除以 √d_k → Softmax 不容易过早饱和
```

它的目的不是让所有词一样重要，而是避免训练刚开始时注意力过度极端。模型仍然可以重点关注某些 Token，只是这个过程更稳定。

## 4. 残差连接和归一化保护信息

一个 Transformer 子层可以简化理解为：

```text
输入 x
  ├───────────────┐
  ↓               │
Attention 或 FFN  │
  ↓               │
输出结果 + 原始 x ←┘
  ↓
归一化
```

### 残差连接：保留一条原路

残差连接把子层输出和原输入相加：

```text
y = x + F(x)
```

可以把它理解为：每层不必重新写掉全部信息，只需要在原表示上增加一部分修改。即使某层暂时没有学好，原始信息仍有一条较短的路径可以继续传递。

残差连接也让梯度更容易传回前面的层，缓解深层网络中的梯度消失和训练困难。

### 归一化：控制数值尺度

LayerNorm 或 RMSNorm 会把每层表示控制在较稳定的数值范围。否则网络堆叠几十层甚至上百层后，数值可能越来越大或越来越小。

残差连接不是完整备份每一层的“原始句子”，归一化也不是防止语义发生变化。更准确地说，它们共同提供了稳定的信息和梯度通道，使深层 Transformer 更容易训练。

## 5. 位置编码告诉模型词序

自注意力本身主要根据 Token 内容计算关系。如果不给任何位置信息，下面两句话包含相同的词，模型很难只靠注意力区分顺序：

```text
猫追狗
狗追猫
```

但它们的意思完全不同。

位置编码相当于给每个 Token 增加一个“座位号”：

```text
猫（位置 1） 追（位置 2） 狗（位置 3）
狗（位置 1） 追（位置 2） 猫（位置 3）
```

早期 Transformer 使用正弦、余弦位置编码；许多现代大模型使用 RoPE，把相对位置信息融入 Query 和 Key。还有可学习位置嵌入、ALiBi 等方案。

它们的实现不同，但目标相同：让模型知道 Token 的先后、相对距离和排列关系。

## 6. Attention 和 FFN 分别做什么

一个 Transformer 层通常可以粗略拆成两种工作：

```text
Attention：Token 之间交流
FFN：每个 Token 单独加工
```

### Attention 像调度员

Attention 决定当前 Token 应该从哪些位置拿信息，以及分别拿多少。

处理“巴黎是法国的首都”时，“首都”可能需要重点关注“巴黎”和“法国”；处理代词时，后面的“它”可能需要回看前面的名词。

所以 Attention 很像调度员：它不只是保存某个事实，而是根据当前上下文动态安排信息流向。

### FFN 像每个 Token 的加工车间

Attention 混合完上下文信息后，每个 Token 会独立经过同一套 FFN。FFN 通常先升维、经过非线性激活，再降回隐藏维度：

```text
4096 → 16384 → 4096
```

它像一个加工车间：把 Attention 收集来的信息摊开，识别和组合特征，再把结果浓缩回原来的维度。

研究发现，FFN 中确实可以定位到与部分事实、概念和语言模式相关的神经元，因此把 FFN 比作“知识库”有一定直觉价值。但不能把它理解成传统数据库：

- 事实不是以一行一条记录的形式保存。
- 同一知识可能分散在许多层和参数中。
- Attention、词嵌入和 FFN 都参与知识的表达与调用。
- 模型不能像数据库一样保证准确查询和及时更新。

因此更稳妥的比喻是：**Attention 像信息调度员，FFN 像存有大量模式的加工车间。**

## Transformer 为什么比 RNN 更强

| 对比项 | RNN / LSTM | Transformer |
|---|---|---|
| 句内计算 | 按时间步顺序执行 | 训练时所有输入 Token 可并行 |
| 远距离关系 | 信息逐步传递，路径随距离变长 | 一层注意力即可直接连接任意 Token |
| GPU 利用率 | 序列依赖限制并行度 | 主要操作是适合 GPU 的大矩阵乘法 |
| 长文本记忆 | 容易受隐藏状态容量和传播距离影响 | 可直接读取上下文中的不同位置 |
| 扩展规模 | 扩大训练规模较困难 | 容易做成更深、更宽和更大的模型 |

RNN 的优势是状态可以按时间流式更新，单步计算和内存需求可能更小。对于传感器流、小型时序任务或严格在线处理，它仍可能更合适。

Transformer 的关键优势在于训练效率和信息路径。它能用大量 GPU 并行训练，也能直接建模全局依赖，这两点共同推动了大规模预训练。

## Transformer 为什么比 CNN 更适合语言

CNN 通过卷积核观察局部窗口。一个大小为 3 的卷积核，首先只能看到相邻的几个 Token：

```text
[我 喜欢 吃] [喜欢 吃 苹果] [吃 苹果 因为] ...
```

如果两个词距离很远，就要堆叠更多卷积层、扩大卷积核，或者使用空洞卷积，才能让它们的感受野相遇。

而自注意力从第一层开始就能看到全句。它的连接权重还会随输入内容动态变化：

- CNN 的卷积核规则相对固定，主要由位置邻近关系决定信息怎样聚合。
- Attention 会根据当前句子内容，动态决定哪些 Token 应该强连接。

| 对比项 | CNN | Transformer |
|---|---|---|
| 擅长关系 | 局部、平移不变的模式 | 全局且随内容变化的关系 |
| 感受野 | 随网络层数逐渐扩大 | 单层即可覆盖整个序列 |
| 信息聚合 | 使用共享卷积核 | 使用输入相关的注意力权重 |
| 并行计算 | 可以并行 | 可以并行 |
| 长距离依赖 | 需要多层或特殊卷积 | 任意位置可以直接建立联系 |

CNN 并不弱。图像具有很强的局部结构，卷积的先验能够提高数据效率，而且高分辨率任务中卷积成本更容易控制。Transformer 的优势是更通用、更容易表示全局和动态关系，而不是在所有任务、所有数据规模下都必然优于 CNN。

## Transformer 也有代价

标准自注意力需要计算长度为 `n` 的 Token 两两之间的关系，时间和注意力矩阵内存复杂度通常是 `O(n²)`。

```text
Token 数翻倍 → 注意力关系数量大约变成 4 倍
```

这使长上下文成本迅速增加。Transformer 还需要大量数据和算力，缺少 CNN 的局部先验，在小数据任务上未必占优。

现代系统使用 FlashAttention、稀疏注意力、滑动窗口注意力、KV Cache 和线性注意力等方法降低成本，但这些优化也会带来新的工程复杂度。

## 最后总结

Transformer 相比 RNN 和 CNN 的核心优势可以概括成三句话：

1. **算得快**：训练时 Token 可以并行，适合 GPU 的大规模矩阵计算。
2. **连得近**：任意两个 Token 可以直接建立联系，长距离信息不必逐步传递。
3. **扩得大**：注意力、FFN、残差和归一化组合成稳定的模块，容易堆叠并扩大模型规模。

RNN 像按顺序传话，CNN 像用窗口逐块观察，Transformer 则像让所有词先开一次全体会议，再让每个词回到自己的加工车间继续整理信息。

这套结构未必在所有场景都最省资源，但它特别适合“大数据 + 大模型 + 大算力”的预训练路线，这正是它成为现代大语言模型基础架构的主要原因。
